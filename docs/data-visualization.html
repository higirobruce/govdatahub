Dashboards & Charts.

Turn any SQL query result into a chart, arrange charts on a responsive grid, and share the dashboard as a link, JSON export, or embedded widget.

Overview

What it does

DataGate's visualization layer sits on top of the query engine. Every chart is fed by a saved query, a cross-database query, or an ad-hoc SQL result. Once charted, widgets live on a dashboard — a freely arranged 12-column grid that survives resizing, reordering, and sharing.

Source

SQL results

Charts are derived from query output. Run a query in the editor, then "Add to Dashboard".

Render

Apache ECharts

All nine chart types render through ECharts. Each chart can be exported as a PNG from the widget menu.

Layout

Responsive grid

Widgets sit on a 12-column grid. Drag to reposition, drag corners to resize. Lock with Preview mode.

Reference

Chart types

Nine visualization types. Pick by question, not by aesthetic — line for trend, bar for comparison, pie for share of a whole.

Line

Trends over a continuum

Single or multi-series. Toggle area fill for cumulative emphasis.

Bar

Category comparison

Vertical, horizontal, or stacked. Best for discrete groupings.

Pie

Share of a whole

Use sparingly — five slices or fewer. Donut variant available.

Area

Cumulative trend

Stacked area for compositional change over time.

Scatter

Correlation

Two numeric axes. Optional size dimension for a bubble effect.

Radar

Multi-axis profile

Compare entities across 3–8 quantitative dimensions.

Heatmap

Density grid

Two categorical axes, one numeric value mapped to color.

Gauge

Single metric

A KPI against a target. One number, one band.

Funnel

Sequential conversion

Ordered stages with monotonically narrowing values.

Tip

Chart type is configurable after creation. Adding a widget with the wrong type isn't a one-way door — switch it from the widget's ChartConfigPanel.

Guide

From query to dashboard

The end-to-end flow takes a few minutes. Charts are staged in localStorage between the query page and the dashboard, so you can build up several before committing to a layout.

  1. Run a query

    Open /query, choose a connection, and execute SQL. Results appear in the table below the editor.

  2. Add the result to a dashboard

    Click Add to Dashboard. Pick a chart type and map columns to axes. The chart is staged under the pendingDashboardCharts key in localStorage.

  3. Open the dashboard builder

    Navigate to /dashboards and either open an existing dashboard or create a new one. Use Load Pending Charts to pull staged widgets in.

  4. Arrange the layout

    Drag widgets to reposition; drag the bottom-right corner to resize. The grid is 12 columns wide and reflows on smaller screens.

  5. Save and share

    Give the dashboard a name and description, then save. Share via link, JSON export, email, or copy-to-clipboard from the share modal.

Heads up

Pending charts live in browser localStorage — clearing site data or switching browsers loses them. Save the dashboard before closing the tab.

Reference

API endpoints

The dashboard module is mounted under /dashboard. All endpoints require a JWT and scope to the caller's organization.

MethodPathPurpose
GET/dashboard/statsAggregate metrics for the org's dashboards.
GET/dashboard/catalogDataset catalog for use in widgets.
GET/dashboard/sharesList shared dashboards in the org.
POST/dashboard/sharesCreate a shareable link for a dashboard.
GET/dashboard/analytics/query-performanceQuery execution metrics over a time window.
GET/dashboard/analytics/shared-datasetsStats on which datasets are shared most.
GET/dashboard/analytics/data-freshnessFreshness signals per dataset.
GET/dashboard/analytics/connection-healthConnection status and latency per source.

Example — list dashboard stats

// All requests must include the JWT in the Authorization header.
const res = await fetch("/api/dashboard/stats", {
  headers: { Authorization: `Bearer ${token}` },
});
const stats = await res.json();

Testing

Things to verify

When testing the visualization feature end-to-end, walk through these checks. A pass means the user can move through the workflow without rolling back.

Note

Run the app with pnpm dev and exercise the flow against a live connection. Mocked data hides axis-mapping bugs.

Smoke checklist

StepExpected
Run a query that returns rows on /queryResult grid renders. Add to Dashboard is enabled.

Edge cases worth poking

  • Query returns zero rows — widget should show an empty state, not a crashed chart.
  • Query column is renamed in SQL between staging and load — confirm the axis mapping degrades cleanly.
  • Clear localStorage mid-flow — confirm pending charts are reported as missing rather than silently dropped.
  • Dashboard with 12+ widgets — grid still scrolls; ECharts instances are not double-mounted.
  • Share a dashboard, then revoke the share — the link should 404 cleanly, not leak an empty shell.

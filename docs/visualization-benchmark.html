Where we stand.

A side-by-side reading of DataGate's dashboarding against three reference tools — Kibana, Apache Superset, and Metabase — followed by a prioritized list of opportunities to close the gap.

Methodology

How we compared

The benchmark covers the visualization and dashboarding surface — not connectors, governance, or ML. Each tool was scored on the same nine capability axes drawn from current customer expectations for an analytics product:

  1. Chart catalogue — breadth and depth of chart types.
  2. Authoring UX — how a non-engineer goes from data to chart.
  3. Dashboard interactivity — filters, cross-filters, drill-down, tabs.
  4. Sharing & embedding — links, signed embeds, public access.
  5. Scheduled delivery & alerting — push reports, threshold alerts.
  6. Permissions & multi-tenancy — row-level security, org isolation.
  7. Semantic layer — saved metrics, models, calculated columns.
  8. Performance — query caching, async execution, row limits.
  9. Extensibility — custom charts, plugins, API surface.
Note

Comparisons are based on each project's documented capabilities as of May 2026. Feature support evolves quickly — verify against the latest release before relying on a specific row.

Headline

In one paragraph

DataGate ships a focused, modern dashboard surface — nine chart types, a 12-column responsive grid, link/JSON/email sharing, PNG export — and is the only tool in this group with native cross-database joins via PostgreSQL FDW. Where it lags is in the layer above charts: dashboard filters, scheduled email/Slack delivery, signed embeds, a semantic layer, and a no-SQL question builder. The reference tools all ship those, and most users expect at least three of them by default.

DataGate strength

Cross-database joins

Native FDW-backed joins across heterogeneous sources. Kibana is Elastic-only; Superset/Metabase need a warehouse to join across.

Closest gap

Dashboard filters

None of DataGate's widgets share a date range or dropdown today. All three reference tools ship cascading filters out of the box.

Biggest opportunity

Scheduled delivery

Existing pipeline cron infra makes weekly PDF/email/Slack delivery a high-leverage, low-cost addition.

Category notes

Where each tool excels

Charting catalogue

Superset is the broadest, with 50+ chart types including Sankey, treemap, waterfall, mixed-axis, and deck.gl-powered maps. Metabase keeps the core list tight (≈25) but every type ships with smart defaults that "just look right". Kibana's Lens generates suggestions based on the field types you drop in. DataGate's nine ECharts types are competitive for shape coverage but miss the high-value tiles users notice on day one — pivot table, big-number/KPI, and a geographic map.

Authoring UX

Metabase's "Ask a question" flow is the gold standard for non-SQL authors: pick a model, summarize by, filter, group. Kibana Lens is the closest peer. Superset's Explore screen is more discoverable than its SQL Lab but still favors users who know what aggregation they want. DataGate today is SQL-only — anyone who can't write a query is locked out of authoring, which excludes most business users.

Dashboard interactivity

The three reference tools all ship cascading filters and at least one mode of cross-filtering (click a bar → filter the rest). Metabase's "click behavior" is the most flexible: each click target can be configured to drill, link to another dashboard, or update parameters. DataGate today renders each widget independently — a single date range applied to all widgets requires editing the underlying SQL of each.

Sharing & embedding

Metabase and Superset both ship signed-JWT embeds where the host app can inject per-user filters at render time — this is the unlock for white-labeling analytics inside another product. Kibana has Shareable Snapshots and full iframe embeds. DataGate's current sharing is a static link or JSON dump — enough for internal handoff, not enough for embedded analytics.

Scheduled delivery & alerts

All three reference tools have a first-class scheduled-delivery story: weekly PDF to a Slack channel, threshold alert when a KPI crosses a line. DataGate has the underlying scheduler infrastructure already (NestJS ScheduleRegistry, cron, and a pipeline runner) — the missing piece is a delivery worker that snapshots a dashboard and pushes it to a destination.

Semantic layer

Superset's datasets-with-metrics and Metabase's models are how power users avoid copy-pasting COUNT(DISTINCT user_id) across thirty charts. They also enable reusable calculated columns and percentile metrics. DataGate's current saved query is the unit of reuse — closer to Superset's "virtual dataset" but without metric definitions.

Performance

Superset's Redis-backed cache and Celery workers, plus Kibana's index-time aggregations, let dashboards open in under a second even at scale. DataGate caps queries at 30s and 10k rows with no caching layer — fine for crisp ad-hoc work, brittle as soon as a dashboard sits behind a slow remote source.

Cross-database — DataGate's lead

This is the genuinely differentiated capability. Superset and Metabase can connect to many sources but cannot join across them without first landing data in a warehouse. Kibana is Elastic-only. DataGate's FDW-backed query path means a join across a Postgres operational store and a MySQL CRM is a first-class feature. Worth protecting and surfacing more prominently in the UI.

Backlog

Opportunities to close the gap

Each opportunity is sized as P0 (must-have for parity), P1 (strong table-stakes), or P2 (differentiator or polish). Effort is a rough engineering estimate.

P0 Dashboard-level filters

Add a filter bar above the grid with date range, dropdown, and free-text controls that flow into each widget's underlying query via a parameter substitution layer. Cascading filters (region → city) follow naturally.

Effort: M · Unblocks: cross-filter on click, scheduled delivery with parameters

P0 Scheduled email / Slack delivery

Reuse the existing pipeline cron infra. A delivery job snapshots the dashboard (using the existing PNG export per chart, composed into a PDF), then sends to a configurable list of channels. Use organization SMTP config or a Slack webhook stored on the org.

Effort: M · Reuses: ScheduleRegistry, PipelineRun entity pattern

P0 Big-number / KPI widget

The single most asked-for chart on day one. Pair a number with a sparkline, a percentage delta vs a prior period, and a conditional color band. Trivial to add as a tenth ECharts component.

Effort: S · Reuses: existing chart component pattern

P0 Pivot / crosstab table widget

A two-axis aggregating table. Powered by a simple group-by-and-pivot transformer over query results. Use @tanstack/table or similar — does not need a third-party pivot engine for v1.

Effort: M

P0 Parameterized queries

Allow {{date_range.start}}-style placeholders in saved-query SQL, bound to dashboard filters or share-link parameters. Without this, dashboard filters can't reach the widgets.

Effort: M · Blocks: dashboard filters, signed embeds with row-level filters

P1 Cross-filter on click

Clicking a bar/slice emits a filter to the rest of the dashboard. Sits on top of the dashboard-filter and parameterized-query work — wire ECharts click events to the filter state.

Effort: S (after filters) · Builds on: dashboard filters

P1 Signed-JWT embed mode

Issue a short-lived JWT scoped to { dashboardId, parameters }. An embedding host app calls a backend endpoint, gets a token, and renders DataGate in an iframe with per-user filters injected. Unlocks white-label analytics.

Effort: M · Depends on: parameterized queries

P1 Query result caching

Redis-backed cache keyed on (query, params, connectionId, orgId) with a configurable TTL per saved query. Lifts dashboard re-open from "rerun all widgets" to "render from cache".

Effort: M · Massive perceived-performance win

P1 Text / markdown widget

A non-chart widget that renders markdown. Essential for executive dashboards where context lives next to the numbers. react-markdown is already a dependency.

Effort: XS

P1 Threshold alerts

"When KPI X crosses Y, email Z". Same scheduled-delivery pipe with a predicate. Aim for the 90% case (compare a single number to a threshold) before adding anomaly detection.

Effort: S · Reuses: scheduled delivery

P1 Auto-refresh interval

Per-dashboard "refresh every N minutes" toggle. Lightweight — a SWR refreshInterval on each widget driven by dashboard-level state. Critical for ops-dashboard use cases.

Effort: XS

P1 Dashboard PDF / CSV export

One-click full-dashboard PDF and per-widget CSV. Server-side render via Puppeteer (a known DataGate dependency for catalog screenshots) or client-side via the existing PNG path.

Effort: S

P1 Geo map widget

A choropleth (country/region shading) and scatter-on-map. ECharts has both built in — add a tenth chart type and a basic geo-column convention (latitude/longitude, ISO country code).

Effort: M

P2 Lightweight "Ask a question" builder

A schema-aware UI that lets users pick a table, summarize by an aggregation, group by a column, and filter — then generate the SQL behind the scenes. Doesn't need to match Metabase's full surface; even a 60% version expands the addressable audience meaningfully.

Effort: L · Major UX investment

P2 Semantic layer (saved metrics)

Allow a saved query to declare named metrics (active_users := COUNT(DISTINCT user_id WHERE active)). Widgets reference the metric, not the SQL — change the definition once, update everywhere. Pairs naturally with the cross-database query feature.

Effort: L

P2 Dashboard tabs / pages

Group widgets into named tabs inside one dashboard. Today each "view" requires a separate dashboard, which fragments navigation.

Effort: M

P2 Row-level security on shares

When sharing, apply an implicit filter derived from the recipient's identity (e.g. WHERE region = $user.region). Strong tie-in with the multi-tenant org model. Needed before DataGate is safe to embed in an external customer-facing product.

Effort: L · Pairs with signed-JWT embed

P2 Drill-to-detail

Click a chart element → open the underlying rows. The SQL transformation is mechanical (add a WHERE for the clicked group); the UI affordance is a modal table.

Effort: M

P2 Custom chart plugin API

Lets teams ship niche visualizations (Sankey, waterfall, custom maps) without forking. A narrow plugin contract — receives query results, returns a React node — keeps the surface small.

Effort: L

P2 Dashboard version history

Snapshot on save, with restore. Cheap once dashboards are stored as JSON in a single column — append-only history table keyed on dashboard id.

Effort: S

P2 Annotations on time-series

Drop a vertical marker on a line chart ("v2 launch", "incident"). Stored per dashboard, rendered as ECharts markLine with a tooltip.

Effort: S

Sequencing

Suggested roadmap

Three milestones, each ~6–8 weeks of focused work. The ordering minimizes rework: filters and parameterization land first because they unblock everything downstream.

Milestone Goal Scope
M1 Interactive dashboards Make dashboards feel alive. Parameterized queries · Dashboard filters · Cross-filter on click · Big-number widget · Pivot table · Text/markdown widget · Auto-refresh · Annotations
M2 Delivery & performance Get dashboards out of DataGate and in front of people, fast. Query result caching · Scheduled email/Slack delivery · Threshold alerts · Dashboard PDF/CSV export · Async query execution · Dashboard version history
M3 Embed & semantic layer Open the door to embedded analytics and reusable metrics. Signed-JWT embed mode · Row-level security on shares · Saved metrics & calculated columns · Dashboard tabs · Geo map widget · Lightweight question builder
Tip

M1's parameterized-query work is the most leveraged investment on this list — five later items collapse to days of work once it lands. Resist the temptation to ship a filter UI without it.

Caveat

Effort estimates are calibrated to the current team and codebase. They assume one engineer per milestone working at typical pace, and exclude design and QA.
